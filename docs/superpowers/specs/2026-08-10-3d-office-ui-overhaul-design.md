# AI CEO — 3D 오피스 UI/디자인 전면 개편 설계

작성일: 2026-08-10
상태: 승인 대기

## 1. 배경과 목표

현재 `index.html`(단일 100KB 파일)은 SVG로 그린 2D 비주얼 노벨이다. 이를 폐기하고,
3D 오피스 공간을 WASD로 걸어다니며 ARIA와 팀원을 통해 스토리를 진행하는 형태로 전면 교체한다.

이전 버전의 화면 구성·렌더링 방식은 유지하지 않는다. 스토리 데이터와 상태값 정의만 계승한다.

### 이번 범위에 포함되는 것

- 3D 오피스 공간 렌더링 (백드롭 사진 + 3D 지오메트리 + 조명)
- WASD 이동 + Shift 달리기 + 3인칭 백뷰 카메라
- 캐릭터 5인 빌보드 배치 + 머리 위 네임태그
- ARIA 홀로그램 (구체·궤도·프로젝터·파티클) + 4상태 컬러 시스템
- HUD 전체 (목표 카드, 스탯 패널, 메뉴 독, 조작 가이드, 선택지 3카드)
- 진행 방식: ARIA 말풍선 클릭 / 회의하기 버튼
- 기존 스토리를 순수 데이터로 추출해 재사용

### 이번 범위에서 제외되는 것

- E키 개별 NPC 상호작용 (다음 단계)
- 메뉴 독 각 패널의 내용 구현 (팀/기록/인벤토리/설정은 껍데기까지만)
- 스토리 자체의 재작성 (나중에 별도 작업)
- 사운드, 저장/불러오기

## 2. 핵심 설계 원칙

**스토리 격리.** 사용자가 "스토리는 나중에 갈아엎겠다"고 명시했다. 따라서 렌더링·UI·상태
로직은 스토리 내용을 일절 알지 못해야 한다. 스토리는 `src/game/story.data.js` 한 파일에
순수 데이터로만 존재하며, 이 파일을 통째로 교체해도 나머지 코드는 손대지 않는다.

**사진 레이어와 3D 레이어의 분리.** 이미지 1·2는 AI 생성 사진이라 모니터링 같은 섬세한
디테일은 실시간 3D로 재현 불가능하다. 사진은 원경(고정)에, 3D는 중경(이동 가능)에 둔다.

**작은 모듈.** 파일 하나가 하나의 책임만 갖는다. 현재의 100KB 단일 파일이 편집을 어렵게
만들던 문제를 반복하지 않는다.

### 3.4 플레이어 캐릭터 조달

`사장 이미지파일.png`는 정면 3/4 흉상이다. 게임 화면은 3인칭 백뷰 전신이므로 이 사진만으로는
월드 안 캐릭터를 만들 수 없다. 상반신에서 전신을 만들어내는 것은 이미지 생성 도구가 필요하며
코드로는 불가능하다(그리면 일러스트가 되어 포토리얼 포트레이트 5장과 톤이 어긋난다).

확정된 디자인 사양 — 이후 어떤 방식으로 조달하든 아래를 고정한다:

- 흑발 미디엄 렝스 머쉴렛, 목덜미까지 내려옴
- 보라 홀로그램 AR 글래스 (정면 뷰에서만 보임)
- 검정 택티컬 테크웨어 재킷, 솔기·어깨에 보라 LED 라인
- 오른팔 상단 보라 `CEO` 패치, TRIPLEDOT 로고 패치
- 유틸리티 스트랩과 버클, 검정 택티컬 팬츠, 검정 부츠
- 배경은 포트레이트 5장과 동일한 하늘색 단색 `#A8CFE8` (크로마키 일관성)

**단계적 조달.**

1. 지금: 위 사양을 반영한 3D 피규어(실루엣 수준, 검정 재킷 + 보라 LED 라인)로 진행
2. 이후: `ceo_back.png` 확보 시 빌보드로 교체

교체 지점은 `src/world/player-figure.js` 한 곳으로 격리한다. 이 파일은 처음부터
"피규어 렌더링" / "빌보드 렌더링" 두 구현을 스위치할 수 있는 형태로 작성하며,
이미지 파일 존재 여부로 자동 분기한다. 나머지 코드는 어느 쪽인지 알 필요가 없다.

## 5. 3D 공간

### 5.1 3층 구조

**원경 (사진).** 통유리 야경, 안쪽 서가·벽. 이미지 1·2에서 크롭해 큰 평면으로 세운다.
카메라에서 멀고, 약한 블러와 밝기 감쇠로 배경임을 명확히 한다. 이동해도 시차가
거의 없도록 충분히 멀리 둔다.

원본 사진에 찍힌 인물은 전부 제거한다. 3D 빌보드 캐릭터와 이중으로 보이면 안 된다.
사람이 없는 영역(창밖 야경, 천장, 벽면 상단, 서가)만 골라 크롭하는 것을 우선하고,
불가피하면 주변 텍스처로 덮는다. 원본 사진의 소실을 허용받았으므로 크롭 결과가
원본과 달라져도 무방하다.

**중경 (3D).** 바닥, 책상 열, 모니터, 파티션, 회의 테이블, ARIA 프로젝터 받침, 의자.
어두운 러프 재질 + 바닥에 약한 반사. 플레이어가 실제로 걷고 부딪히는 층.

**조명 (3D).** 위에서 내려오는 따뜻한 펜던트 스팟과, 아래에서 올라오는 차가운 모니터
emissive의 대비. 이미지 1·2의 인상 대부분이 이 대비에서 나온다.

### 5.2 레이아웃

프로필 시트의 `자리` 항목을 따른다.

| 구역 | 인물 | 위치 |
| --- | --- | --- |
| 개발 존 (가장 안쪽) | 이서연 | 좌측 안쪽 |
| QA 테스트 존 | 정유나 | 좌측 중앙 |
| 아트 & 마케팅 존 (창가) | 최민 | 우측 창가 |
| 회의 테이블 | 박지훈 | 중앙 |
| 회의실 창가 | 한도윤 | 우측 안쪽 |
| ARIA 프로젝터 | ARIA | 중앙 책상 위 |

플레이어 시작 위치는 입구 쪽, 카메라가 사무실 전체를 보는 방향.

### 5.3 카메라

이미지 1·2의 앵글을 재현한다.

- 3인칭 백뷰, 플레이어 뒤쪽 상단
- 카메라 높이 약 1.6m, 약간 내려다보는 각도
- 좁은 화각 (FOV 약 38°) — 망원 압축감이 사진의 인상을 만든다
- 플레이어는 화면 하단 좌측~중앙에 위치
- 이동 시 부드럽게 따라오되 회전은 지연을 둔다

## 6. 캐릭터

### 6.1 빌보드

알파 PNG를 평면에 매핑하고 Y축만 카메라를 향하게 회전시킨다(수직축 고정 빌보드).
바닥에 접지 그림자를 깔아 공간에 서 있는 느낌을 준다. 씬 조명의 색조를 약하게
곱해 배경과 톤을 맞춘다.

### 6.2 네임태그

3D 월드 좌표를 화면 좌표로 투영해 DOM 요소로 그린다. 캔버스 텍스처가 아니라 DOM이므로
항상 선명하고 한글 폰트가 깨지지 않는다.

- 이름(굵게) + 직책(작게)
- 색상은 캐릭터 컬러
- 거리에 따라 투명도 조절, 일정 거리 밖이면 숨김
- 가림 처리는 하지 않는다 (이미지 1·2도 항상 보임)

### 6.3 캐릭터 데이터

| # | 이름 | 직책 | 나이 | 색상 | 대표 대사 |
| --- | --- | --- | --- | --- | --- |
| 01 | 이서연 | 리드 개발자 | 27 | 보라 / 블랙 (정정됨) | "감이 아니라 데이터로 말하세요." |
| 02 | 정유나 | QA 인턴 | 22 | 민트 / 화이트 | "대표님... 이상한데요?" |
| 03 | 최민 | 아트 & 마케팅 | 25 | 오렌지 / 베이지 | "우리가 만드는 게임의 색깔이 사라질 수도 있어." |
| 04 | 박지훈 | 공동 창업자 / PM | 29 | 그레이 / 브라운 | "자금이 3주밖에 안 남았습니다." |
| 05 | 한도윤 | 퍼블리셔 / 사업개발 이사 | 34 | 블랙 / 골드 | "대표님도 알고 계셨잖아요." |

성격·말투·역할·소품·ARIA와의 관계는 프로필 시트 내용을 `characters.data.js`에 그대로 옮긴다.

### 6.4 프로필 시트에 없는 등장인물

레거시 `index.html`의 `CAST`에는 프로필 시트의 5인 외에 두 명이 더 있다.
스토리 후반부(`s10_press`, `s11_reveal`)에 실제로 등장하며, 대사가 있다.

| id | 이름 | 역할 | 포트레이트 |
| --- | --- | --- | --- |
| `sera` | 오세라 | 기자 | 없음 |
| `taeseok` | 강태석 | ARIA 운영사 · 전략 총괄 | 없음 |

둘 다 사무실 상주 인원이 아니므로 자리를 주지 않고, 캐릭터 색으로 물들인
반투명 실루엣 빌보드로 렌더한다. 포트레이트를 확보하면 팀원 5인과 같은
크로마키 파이프라인을 태워 교체한다.

캐릭터 id는 레거시 표기를 그대로 쓴다. 한도윤은 `doyoon`이 아니라 `doyun`이다.
`story.data.js`의 `beat.w`가 이 id를 참조하므로 바꾸면 대사의 화자가 끊긴다.

## 7. ARIA

### 7.1 구성

- 중심 구체: 와이어프레임 격자 + 내부 노드 파티클, 강한 발광
- 이중 궤도링: 서로 다른 축으로 느리게 회전
- 프로젝터 받침: 계단형 원반, 상단에서 빛 원뿔이 올라감
- 상승 파티클: 받침에서 구체로
- 바닥 반사와 주변으로 퍼지는 포인트 라이트

### 7.2 4상태 컬러 시스템

상태는 테마 토큰 하나로 관리하며, 전환 시 다음이 **동시에** 물든다:
구체 발광 / 궤도링 / 포인트 라이트 / 바닥 반사 / 말풍선 테두리와 제목 / HUD 액센트.

| 상태 | 색 | 라벨 | 트리거 |
| --- | --- | --- | --- |
| `neutral` | 보라 | (없음) | 평상시, 일반 대사 |
| `suggest` | 초록 | ARIA 제안 | 방법을 제시할 때 |
| `recommend` | 파랑 | ARIA 추천 | 특정 선택지를 밀 때 |
| `warn` | 빨강 | ARIA 비추천 ⚠ | 경고할 때 |

`warn` 상태에서는 이미지 3처럼 경고 아이콘과 미세한 글리치가 추가된다.
상태 전환은 약 0.4초 보간으로, 색이 튀지 않게 한다.

### 7.3 3단계 성격 변화

프로필 시트의 초반/중반/후반 구분을 `story.data.js`의 각 비트가 지정한다.
렌더링 코드는 단계를 알 필요가 없고, 대사 톤만 데이터로 달라진다.

## 8. HUD

이미지 1과 2의 요소를 통합한다. 메뉴 독은 **이미지 2의 우측 세로형**을 채택한다.
3D로 이동할 때 화면 하단을 가리지 않기 때문이다.

| 위치 | 요소 | 내용 |
| --- | --- | --- |
| 좌상단 | 목표 카드 | 다이아 아이콘 + 현재 목표 + 서브 안내 |
| 우상단 | 스탯 패널 | DAY n / 요일, 자금 ₩, 그 아래 AI 의존도 바 |
| 우측 세로 | 메뉴 독 | 팀 / 기록 / 인벤토리 / 설정 |
| 좌하단 | 조작 가이드 | 이동 WASD, 달리기 Shift, 상호작용 E |
| NPC 머리 위 | 네임태그 | 이름 + 직책 |
| ARIA 옆 | 말풍선 | 이름 + 배지 + 대사 |
| 하단 중앙 | 선택지 | 3카드 |
| 하단 최하단 | 경고문 | "선택은 이후 되돌릴 수 없습니다." |

### 8.1 시각 언어

- 패널: 반투명 짙은 남색 배경, 1px 미광 테두리, 약한 배경 블러, 작은 모서리 반경
- 서체: 시스템 한글 산세리프. 레이블은 작고 자간을 넓히고, 수치는 크고 굵게
- 액센트: ARIA 현재 상태색을 따라감
- 애니메이션: 등장 시 아래에서 위로 살짝 떠오르며 페이드

### 8.2 선택지 카드

이미지 2를 따른다. 카드 하나에:

1. 번호 배지 (1/2/3) — 카드마다 다른 색
2. 제목 (굵게)
3. 설명 2~3줄
4. 구분선
5. 스탯 변화 (예: `자금 -100,000` `신뢰도 +5`) — 증감에 따라 색 구분

호버 시 살짝 떠오르며 테두리 발광. 숫자 키 1/2/3로도 선택 가능.

## 9. 진행 방식

세 가지 경로로 다음 비트로 넘어간다.

**경로 A — ARIA 말풍선 클릭.** ARIA가 말할 때 홀로그램 옆에 말풍선이 뜬다.
말풍선 또는 ARIA 홀로그램을 클릭하면 진행한다. 대기 중에는 홀로그램이 미세하게
맥동해 클릭 가능함을 알린다.

**경로 B — 회의하기.** 메뉴 독의 `팀`에서 회의하기를 누르면 NPC들이 회의 테이블
쪽으로 이동해 플레이어 앞에 정렬한다. 정렬이 끝나면 클릭해서 진행한다.

**경로 C — 선택지.** 선택지 3카드가 떠 있는 동안에는 A와 B가 잠긴다.
카드를 골라야만 다음으로 넘어간다.

진행 중 이동은 항상 가능하되, 선택지가 떠 있을 때는 카메라가 선택 대상 쪽으로
부드럽게 정렬된다.

## 10. 상태값

`PROJECT_BIBLE.md` 7절의 정의를 그대로 계승한다:
`cash`, `revenue`, `trust`, `morale`, `aiDependence`, `reputation`, `productQuality`.

HUD에 상시 노출되는 것은 `cash`와 `aiDependence` 둘뿐이다(이미지 2 기준).
나머지는 메뉴 독의 `기록`에서 확인한다. 화면을 숫자로 채우지 않기 위한 선택이다.

## 11. 성능

- 목표: 데스크톱 브라우저에서 60fps
- 빌보드 6개, 백드롭 평면 2~3개, 오피스 지오메트리는 인스턴싱으로 묶음
- 그림자는 ARIA 포인트 라이트와 펜던트 1~2개만 실시간, 나머지는 접지 그림자로 대체
- 텍스처는 로드 시 리사이즈. 포트레이트는 세로 1024px 상한
- 로딩 화면에서 에셋 프리로드 후 시작

## 12. 검증 기준

- 데스크톱 브라우저에서 설치 없이 실행된다
- WASD로 사무실을 걸어다닐 수 있고, 벽·책상을 통과하지 않는다
- 캐릭터 5인이 각자 자리에 서 있고 네임태그가 따라온다
- ARIA 4상태 전환 시 구체·말풍선·HUD 액센트가 함께 바뀐다
- ARIA 클릭과 회의하기 두 경로 모두로 스토리를 끝까지 진행할 수 있다
- 선택지 3카드가 상태값에 반영되고 HUD 수치가 갱신된다
- `story.data.js`만 교체해도 나머지 코드 수정 없이 동작한다
- 콘솔 에러 없음, 막힌 진행 없음

## 13. 알려진 제약

- 플레이어 월드 캐릭터는 3D 피규어 대체품이다. `ceo_back.png` 확보 시 자동으로 교체된다.
  이미지 생성은 이 프로젝트 도구 범위 밖이므로 외부에서 조달한다.
- 실시간 3D는 원본 AI 생성 사진의 디테일을 그대로 재현하지 못한다.
  목표는 픽셀 일치가 아니라 인상(조명 대비, 색조, 앵글, 밀도)의 일치다.
- 백드롭에서 인물을 제거하면 그 자리의 사무실 디테일도 함께 사라진다.
  빈 자리는 중경 3D 지오메트리(책상·모니터·파티션)로 메운다.
